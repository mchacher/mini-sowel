## Method and limits

- The tool loads every definition of the library, collects the functions of each raw definition and of its `extend[]` entries (the `convert` of each `fromZigbee` converter, the `convertSet` and `convertGet` of each `toZigbee` converter, `configure`, `onEvent`, a functional `exposes`, and the functions found in `meta`, nested objects included), and locates each function's source text (`Function.prototype.toString`) in the library's `dist/**/*.js` files.
- Origin of a function: shared (`dist/converters/`, `dist/lib/` except the brand files, `dist/index.js`), brand (a brand file of `dist/lib/`), device (`dist/devices/<brand>.js`), unknown (found nowhere; counted as device, the cautious side). A text found in several categories takes the widest reuse: shared if it is in shared code, else brand if it is in a brand file, else device.
- Brand files: `lib/adurosmart.js`, `lib/bosch.js`, `lib/develco.js`, `lib/ewelink.js`, `lib/heiman.js`, `lib/heimgard.js`, `lib/ikea.js`, `lib/inovelli.js`, `lib/ledvance.js`, `lib/legacy.js`, `lib/legrand.js`, `lib/lidl.js`, `lib/lumi.js`, `lib/namron.js`, `lib/nodon.js`, `lib/philips.js`, `lib/sonoff.js`, `lib/sunricher.js`, `lib/ubisys.js`, `lib/zosung.js`. `lib/legacy.js` counts as brand code. `lib/tuya.js` is shared: the Tuya datapoint interpreter used by many white labels.
- Class of a definition, the first that applies: Tuya table (`meta.tuyaDatapoints` and no brand, device or unknown function), declarative (every function shared, or no function), brand code (no device function, at least one brand function), device code (at least one device or unknown function). Tuya table and declarative are exportable.
- Device code in configure only: every device or unknown function comes from a `configure`. Such code is often only binding and reporting setup, which an export would carry as a table.
- Standard: every `cluster` of the `fromZigbee` converters is one of the standard clusters (genBasic, genPowerCfg, genOnOff, genLevelCtrl, genScenes, genMultistateInput, lightingColorCtrl, msTemperatureMeasurement, msRelativeHumidity, msPressureMeasurement, msIlluminanceMeasurement, msOccupancySensing, ssIasZone, closuresWindowCovering, hvacThermostat, seMetering, haElectricalMeasurement). A definition with no `fromZigbee` converter is not standard. A converter with no cluster makes the definition not standard.
- Two functions with the same source text count as one shared function.
- Functions whose text is found in no file (unknown, counted as device): 0 distinct. 0 definitions are device code only because of them.
- No definition threw while prepared.
- Brands with no definition in the library (row with 0): Hager.
- Not collected: `endpoint` functions (a data mapping of endpoint names), converter `options`.
- What the measure cannot see: a shared function may still be hard to reimplement; `configure` written in a device file is often only binding and reporting; a function whose text is found in a shared file may be a closure that captures device-specific data.
